What · 02

K3s — un binario, sesenta segundos

¿Por qué K3s y no kubeadm, k0s, minikube?

  • Un binario. ~50 MB. Install en 60 segundos.
  • Trae Traefik, ServiceLB, local-path-provisioner por default.
  • v1.34 ya soporta los CRDs que KServe v0.14 espera.
  • Sin componentes que no uso. Para 1 nodo es el sweet spot.
# un solo comando
$ curl -sfL https://get.k3s.io | sh -

# 60 segundos después
$ kubectl get nodes
NAME       STATUS   ROLES                  VERSION
gpu-node   Ready    control-plane,master   v1.34.1+k3s1

What · 06

RawDeployment vs. Knative

Una decisión de KServe que cuesta entender — y que cambia toda la operación.

RAWDEPLOYMENT   ✓ ELEGIDO

Deployment + HPA, normal.

  • Menos operadores corriendo
  • Sin cold starts de Knative
  • Menos cosas que pueden romper
  • Sweet spot para 1 dev, 1 GPU
KNATIVE   — DESCARTADO

Scale-to-zero, serverless.

  • Más operadores — Activator, Autoscaler
  • Cold starts visibles
  • Sentido si tenés tráfico bursty real y muchos modelos

How · 01

Bootstrap — bash, no Terraform

TensorDock no tiene un provider clean. Para 1 nodo, agregar Terraform es ceremonia que no paga.

#!/usr/bin/env bash
# bootstrap.sh — corre via cloud-init
set -euo pipefail

# 1. Driver NVIDIA (.run installer — ojo con DKMS, war story #2)
sh NVIDIA-Linux-x86_64-570.144.run --silent --no-questions

# 2. Container toolkit — para que containerd vea la GPU
apt-get install -y nvidia-container-toolkit

# 3. K3s — 60 segundos
curl -sfL https://get.k3s.io | INSTALL_K3S_VERSION=v1.34.1+k3s1 sh -

# 4. NVIDIA Device Plugin — registra nvidia.com/gpu en el cluster
kubectl apply -f https://raw.githubusercontent.com/NVIDIA/k8s-device-plugin/...

# 5. Pin el kernel — war story #2
apt-mark hold linux-image-* linux-headers-*

How · 02

El stack de NVIDIA — 3 piezas

Si una de las tres falla, el pod no schedulea. El error es siempre Insufficient nvidia.com/gpu — aunque la causa esté 3 capas más abajo.

CAPA 1 · KERNEL

Driver del host

Expone la GPU al kernel Linux. nvidia.ko.
$ nvidia-smi
CAPA 2 · RUNTIME

container-toolkit

Deja que containerd vea la GPU dentro del container.
/etc/containerd/config.toml
CAPA 3 · K8S

Device Plugin

Registra la GPU como recurso schedulable: nvidia.com/gpu.
DaemonSet, namespace kube-system

How · 05

El manifest — esto es la abstracción

apiVersion: serving.kserve.io/v1beta1
kind: InferenceService
metadata:
  name: qwen3-vl
  annotations:
    serving.kserve.io/deploymentMode: RawDeployment
spec:
  predictor:
    model:
      modelFormat:
        name: vllm
      runtime: vllm-runtime
      image: vllm/vllm-openai:v0.11.0   # NO :latest
      args:
        - --model=Qwen/Qwen3-VL-4B-Instruct
        - --dtype=float16
      resources:
        limits:
          nvidia.com/gpu: 1
          memory: 32Gi

  • HPA

How · 06

Scheduling con una sola GPU

  • RTX 4090 schedulable como nvidia.com/gpu: 1
  • Un pod a la vez puede tomarla.
  • No MIG en consumer GPUs.
  • Time-slicing existe — agrega contention. Para vLLM no vale.
  • Resultado: cola serializada. Esto importa para el rollout.

PARTE 04 / 04

Lessons

Las cuatro cicatrices, una por una. Error real, causa real, fix real.
War story · 01

CUDA forward-compat — Error 804

SÍNTOMA
$ kubectl logs vllm-pod -f
...
CUDA error 804: forward compatibility
  was attempted on non supported HW
# pod arranca → muere → restart loop
CAUSA
  • vllm:latest ships CUDA 13
  • Host driver 570.144 = CUDA 12.8
  • RTX 4090 = consumer → no soporta forward-compat
FIX
# Pin a la única ventana válida
# CUDA 12.x + soporte qwen3_vl

image: vllm/vllm-openai:v0.11.0
Lección general:
Nunca :latest en cargas que tocan kernel/driver. Las imágenes de inference servers pinnean su CUDA — si no coincide con tu driver, error 804.
27
War story · 02

Kernel pin — la GPU desapareció

SÍNTOMA
# post-reboot
$ nvidia-smi
No devices were found

$ kubectl describe node | grep gpu
# nvidia.com/gpu: 0   ← era 1
CAUSA
  • unattended-upgrades subió el kernel
  • Driver instalado via .run — sin DKMS
  • nvidia.ko compilado contra kernel viejo
  • Kernel nuevo arranca → no encuentra módulo → GPU invisible
FIX
# pin el kernel
$ apt-mark hold linux-image-* linux-headers-*

# grub default fijo al kernel viejo
$ grub-set-default 0
$ update-grub

# o mejor: usá DKMS
$ apt install nvidia-dkms-570
Lección general:
Si no usás DKMS, pin el kernel. Si usás DKMS, igual probá un reboot antes de irte a dormir.
28
War story · 03

KServe — el webhook huérfano

SÍNTOMA
$ helm install kserve ...
# cuelga

$ kubectl logs cainjector
failed to inject caBundle: webhook
  references service modelmesh-webhook
  which does not exist
CAUSA
  • Chart oficial instala ModelMesh por default
  • Webhook apunta a un servicio que no existe en RawDeployment
  • cainjector ve webhook roto → refusa inyectar → install hangs
FIX
# 1. borrar el huérfano
$ kubectl delete \
    validatingwebhookconfiguration \
    modelmesh-*

# 2. retry el upgrade
$ helm upgrade kserve --reuse-values
Lección general:
5 min de fix · 2 horas de debug. Cuando un install Helm cuelga, mirá los webhooks antes que los pods.
29
War story · 04

Rolling update deadlock

SÍNTOMA
$ kubectl get pods
NAME            STATUS    AGE
vllm-old-xxx    Running   2d
vllm-new-yyy    Pending   ∞

# Insufficient nvidia.com/gpu
CAUSA
  • RollingUpdate asume N+1 réplicas posibles
  • Con 1 GPU eso no es cierto
  • Nuevo no arranca hasta que viejo libere
  • Viejo no libera hasta que nuevo esté Ready
  • Deadlock infinito.
FIX
spec:
  strategy:
    type: Recreate
    # NO RollingUpdate
Lección general:
Cuando hay un solo recurso scarce (GPU, IP estática, port host) → Recreate. Hay un blip de ~30s de downtime, pero el rollout completa.

Lessons · resumen

Los 4 pins que vos ponés

No los pone KServe. No los pone vLLM. No los pone Kubernetes. Los ponés vos.

PIN · 01

Image tag

No :latest. Nunca. Pin a la versión que corresponde a tu CUDA.
PIN · 02

Kernel

apt-mark hold, grub default. O DKMS para sobrevivir kernel updates.
PIN · 03

Driver

DKMS si podés. Si no, pin manual y monitoreá nvidia-smi post-reboot.
PIN · 04

Strategy

Recreate cuando el recurso es scarce. RollingUpdate asume N+1.
